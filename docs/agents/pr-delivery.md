# PR 交付原则

- **按新增风险验证。** 核对待提交内容与已评审版本、目标基线及验证条件。没有新增风险时，复用有效的评审和测试证据；出现代码变化、冲突或证据缺口时，补做相关验证。仓库明确要求的检查仍须满足。
- **控制提交范围。** PR 优先包含源码、测试、必要说明和关键复现证据。批量原始日志、截图和 trace 按需单独归档，通过摘要和索引保持可追溯；纳入提交前检查必要性与凭据安全。
- **有界等待，核实后重试。** 网络操作设置合理的等待边界。失败或长时间无进展时，先核对远端状态，再决定继续等待或重试；前次操作已成功就进入下一步。以远端提交和 PR 状态确认交付结果，区分已推送、已创建 PR 与已合并。
