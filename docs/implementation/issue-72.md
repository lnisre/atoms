## 实施边界

- 在已有普通身份 PG RPC 的可信产物采用事务中保留旧代码、策略、正式数据与记录；不接受浏览器上传快照。001–003 迁移不改写。
- 历史身份使用独立 UUID；显示序号与 `{code,data}` 并发计数分开。后续 #73 恢复/撤销必须推进并发计数，任务及操作回执不回退。
- 首次正式成果、示例个人副本、明确启用后的待验证成果及功能启用时的已有正式项目建立真实基线。已有项目无法知道原业务保存时间时标明未知，并给出实际基线保存时间；不用项目 `updatedAt` 猜测。
- 新版本替换旧版本时，旧保存点配对替换前最后成功保存的数据。当前保存点与已封存历史分别展示；旧修改记录没有快照时明确不可恢复，不补造代码。
- 历史读取复用账号、项目授权和无缓存 BFF；响应增加独立类型校验。快照读取失败不转换为空数据。
- 历史试用由工作台会话持有独立副本，复用 iframe 数据桥与源码查看器。离开/切换历史丢弃该次历史副本，不改变候选及其试用数据；迟到读取不能在退出或换号后发布。
- 本阶段不展示恢复、撤销或清理按钮。#73 复用保存点读取与身份边界完成操作闭环。

## 当前产物与接续接口

`004_project_history.sql` 追加项目独立数据保存时间、历史身份/序号与私有历史表，覆盖可信首次成果、示例复制、明确启用及采用事务。旧正式项目在迁移事务内建立基线，未知的历史数据保存时间保留为空并说明。`atoms_list_history`/`atoms_get_snapshot` 在普通身份下校验所属项目；历史读取不接受客户端文档。工作台历史请求和数据副本有独立生命周期，当前执行阻断仍在 BFF 执行。

#73 在后续迁移扩展恢复/撤销/清理。当前历史表记录完整 `document`（包括需求、采用记录和策略）及配对 `state`/`has_data`，项目通过 `current_history_id` 指向当前点，`history_sequence` 仅为历史序号，不能用作并发控制。`data_saved_at` 是最后正式数据保存时间；`paired_at` 是配对快照实际保存时间。当前点在采用下一版本前封存；后续恢复必须从数据库原件读取，不使用 `historyTrial.trial`。历史表尚无截断/撤销机制，不得先暴露恢复按钮。

旧 `atoms_private.tasks` 与 `operations` 原样保留，不属于可回退文档。#73 需特别处理恢复→撤销后旧证明与旧回执重放、迟到日志/生成、数据会话释放及同一操作提交后回读失败。
