# #73 恢复、完整撤销与安全清理

规格：[#71](https://github.com/lnisre/atoms/issues/71)、[#73](https://github.com/lnisre/atoms/issues/73)、ADR 0014/0015/0016。接续 `c1ca6b9`，实现 `c9a44be`，审查修复与集中验证入口 `0e8469c`。完整验收见 [#74 报告](../verification/issue-74.md)。

新增 005，001–004 原文不变。普通身份 `atoms_change_history` 以项目行锁和操作回执串行化恢复、撤销与清理。预检查返回可信原件，BFF 重查当前确定性执行规则；实际写入重新检查账号、项目、目标和读取版本。请求仅携带操作、保存点或撤销身份，不接收项目 JSON、策略或试用状态。

恢复前在私有备份中保留完整正式文档、数据、历史及必要依赖，然后同事务切换快照原件并截断后续历史。完整文档即后续服务端生成上下文源。撤销恢复完整原状态，同时推进 code/data 写入计数；任务领取和操作账本始终留在备份之外。只有再次恢复成功才替换备份，只有新代码成功采用才结束资格。旧回执仅确认原提交，不重做旧写入。

清理永久移除快照内容，保留条目、修改记录和对话。服务端保护当前点及有效撤销引用。独立 history_revision 使历史确认过期，不因清理业务数据未变而使候选证明失效。此计数也不随业务恢复回退。工作台保留云端撤销提示，确认中说明替换、截断及舍弃内容；恢复前先明确处理候选，清理允许保留候选。

提交回执到达后立即释放旧数据会话，回读失败继续保留同一操作。`acknowledged` 与 `uncertain` 防止把提交后容量错误误认成事务拒绝；只有确定未提交的容量失败才可释放失败操作、打开实际清理入口。日志队列仍独立重试。
