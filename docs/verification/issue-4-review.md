## 规格轴：确定发现

### [P2] 注释中的 `<head>` 使数据桥接和 CSP 注入失效

位置：[`src/lib/preview-document.ts:52`](../../src/lib/preview-document.ts#L52)。服务端接收路径为 [`src/app/api/generate/route.ts:120`](../../src/app/api/generate/route.ts#L120)；运行错误监听依赖同一注入脚本（`preview-document.ts:26–27`）。

复现条件：模型返回的完整合法 HTML 在实际 head 前包含一个写有 `<head>` 的注释，例如：

```html
<!DOCTYPE html><!-- example <head> -->
<html><head><title>Candidate</title></head><body>
<button disabled id="action">添加任务</button>
<script>
atoms.loadState().then(() => document.getElementById('action').disabled = false);
</script></body></html>
```

预期：平台将桥接脚本及 CSP 注入实际文档头，生成代码能够调用 `window.atoms`；若文档无法安全装配，应明确失败，而非展示一个没有平台运行能力的候选。

实际：正则替换第一个 `<head>` 文本，把整个 guard 插入注释。主审分别验证服务端 POST 接收与真实浏览器运行：

- POST 返回 **200**，原 HTML 原样通过合同校验。
- 浏览器 `typeof window.atoms === "undefined"`，有效 CSP meta 数量为 **0**。
- 生成脚本抛出 `atoms is not defined`，业务按钮仍禁用。
- 平台停留在“等待应用读取数据”，没有运行错误提示，仍允许点击“采用修改”。这不是仅 iframe 加载成功的问题。

影响：符合当前 HTML 入口格式的候选可能无法读取/保存数据，平台的 CSP 与错误监听也同时缺失。iframe 的 `sandbox="allow-scripts"` 仍在；**本次没有证明 sandbox 逃逸、跨项目读写或实际数据泄漏，不作此类推断**。这项缺陷在 HEAD 内已有相同正则算法，不是 M2 新引入的回归；历史真实模型样本未观察到触发。本次是明确标注的受控模型输出，不计为真实模型业务错误。

建议：按真实 HTML 结构找到 head 后注入，或对无法安全装配的文档明确拒绝；增加“head 前注释含标签文本”的服务端到预览回归，确认数据桥接、CSP 和错误反馈均存在。只修正字符串匹配而不验证实际 DOM 不足以闭合此问题。

复现脚本：[comment-head.mjs](assets/issue-4-review/comment-head.mjs)；[原始断言](assets/issue-4-review/comment-head.json)；[截图](assets/issue-4-review/comment-head.png)。在仓库根目录以 Node 24 运行该脚本，需要 `127.0.0.1:3107` 上的当前构建。它只使用测试凭据占位与受控响应，不读取真实模型密钥。
