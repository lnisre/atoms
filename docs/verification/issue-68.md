## 实现和边界

- 游客明确提交的生成意图，在登录成功时取出一次；重复回调或点击不会重新启动。普通登录仍只读账号列表。首次生成真实接团队入口；无产物失败保留需求与任务记录，可编辑补充并明确开始新任务，替换前提供下载机会。保存重试沿用原操作，不调用模型。
- `/api/generate` 的现行与兼容入口统一进入团队协议。服务端从云端已保存项目或签名的上一轮候选确定基础代码、原需求、成功修改上下文和未解决的数据问题。浏览器传入的任意 `baseHtml/context/state/owner` 被拒绝；业务数据不进入模型。旧 M2 HTML 直通请求不再执行付费模型，旧客户端需要刷新。
- HTTP 身份、票据 owner、任务 project/base/version 与实际执行器绑定。WebSocket 仍先验证账号，再用该连接绑定的任务令牌控制；跨账号票据与公开控制请求拒绝。数据库领取记录在启动子进程前去重，重复 HTTP 票据即使跨实例也不会再次启动同一付费任务。沿用 4 分钟、20 次请求、15 秒心跳断线及每实例并发 2 的保护，没有新增账号次数配额。
- 终态产物证明由实际团队监督器签发，包含完整 HTML、助手回复、真实服务端步骤、团队审查、当前策略与成功候选链。普通用户身份与证明缺一不可。数据库校验签名、owner、project、任务领取、预期 code/data 与基础代码 hash，无法通过普通 JWT 直调 RPC 伪造策略、审查或任意代码。
- 首次结果和记录原子保存。受限代码第一次保存即为 `draftResult`，旧 `result` 为不执行的说明页；重开后保留执行阻断、试用和采用限制。只有数据库已保存策略允许时，明确 `使用此版本` 才切换正式数据模式，并递增代码版本。
- 候选和本轮未保存对话仅在页面内；多轮继续使用最新候选。试用通过内存数据副本，明确采用只提交代码和对应修改记录，不接受 trial state。采用失败保留候选和原操作；旧候选与旧代码 iframe 写入会冲突，原操作重放不绕开冲突。正式项目、保存失败内容、候选、待验证试用均有合适的下载/重新载入或退出提示。
- 代码提交返回后，再由服务端签发实际提交完成的日志事件。独立追加只合并对应 task/source/sequence，锁住最新 document，不用旧项目整份覆盖，不改变正式数据或代码版本。代码已保存与日志失败分别展示；多次提交的待追加日志排队保留，可单独重试。
- 页面控制器绑定单个账号/项目/生命周期，管理生成取消、保存、日志和数据会话。自然失效不取消已合法启动的连接；结果留原页面，同账号重登后重试保存。主动退出先提示和允许下载；确认后关闭连接、废弃数据会话、卸载 iframe，迟到结果/回执不能发布到新账号。已授权请求可能在退出后提交，但只属于原账号，已提交内容不撤销。
- 保留旧 IndexedDB 原件且不枚举或认领。未重新挂载旧 `ProjectWorkbench` 的本地初始化。下载为明确的未保存 JSON 副本，包含当时需求、代码、相关记录、待保存正式状态或试用状态；不含认证令牌、签名证明或管理配置，不提供导入承诺。

[ADR 0016](../adr/0016-trusted-cloud-artifacts.md) 记录了普通用户身份与任务产物证明的独立职责。证明有大小限制；若终态证明无法生成，完整代码仍可下载，但不能由客户端补造保存资格。没有后台恢复、跨设备运行任务接续、候选持久化或历史快照功能。
