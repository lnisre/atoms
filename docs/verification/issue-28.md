### 单次修改的真实受控返工准备

`inject-modification-save-defect.py` 是仅用于本地开发的 provider wrapper。只对有 modification 的首次真实 Engineer HTML，将显式 `atoms.saveState(...)` 替换为 `Promise.resolve(...)`；保留注入前和被拒 HTML，不预写修复或改造审查结果。实际四角色仍由原生运行器执行，返工与格式纠正不重置预算。此文件在 tests 下，不复制到生产运行时。

在专用本地网关测试启动器中运行该 wrapper，指定空的 `ATOMS_DEFECT_EVIDENCE_DIR`。使用先前真实阅读初始场次的 `reading-initial-independent.json` 作为 `TEAM_REPAIR_BASELINE`，执行 `live-cross-app.ts --execute --repair`。驱动只发起一个评分/筛选修改任务，要求两个 Engineer 产物和先拒绝后通过的两份审查；同一冻结计划验证注入前通过、被拒代码失败、修复代码通过，再验证试用、采用与恢复。任何前提不满足均失败，不能改写预期。

## 首次失败与修正

1. 新检查 helper 的递归 JSON 类型触发 TypeScript 深度限制；改为跨浏览器边界显式 JSON 编解码。首次构建因此未产出 standalone，紧接着的本地网关启动报缺少 server.js。修正后构建成功再启动。
2. Playwright 的 CommonJS 编译不能运行 helper 中的 import.meta；改为从明确的工作区 package.json 创建依赖解析器。
3. 首次跨应用 4/5：阅读最终独立检查出现 tool-error，后续读取/保存失败项未执行；最初错误摘要未保留 detail，不能断言确切根因。增加逐项证据后阅读单独复验通过。
4. 原有进程停止/截止测试失败于 pid 尚未写出。最小无网络进程探针实测启动 1,046 ms，超过旧测试约 1 秒的准备窗口；将准备等待扩大到 5 秒，并留 10 秒的原始短期限，仍检查终止、零交付、迟到控制 410。产品 240 秒预算不变。接口复验 24/24。
5. 首次完整浏览器回归在宿主机 load average 约 30 时出现 4 失败、1 中断，12 通过、53 未执行，主动中止。新阅读检查的逐项证据显示保存状态仍为“正在保存”，父桥 saveAttempts 为 0，说明固定等待结束时保存消息尚未处理。新检查改为有界状态等待并增加“条件不满足不能通过”的测试；同时保留既有测试超时事实，不将全部失败归为已证实的单一原因。

6. 有界等待后的专项场次 6/7，待办独立检查在保存失败场景开始前提前结束，未满足项保留 not-run；下一轮同一检查通过。第二轮完整回归时 load average 约 42，既有候选用例超时，保留 2 失败/1 中断/64 未运行，不作通过解释。
