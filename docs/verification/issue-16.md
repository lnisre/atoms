## 协议与记录

首次生成浏览器给 `POST /api/generate` 加 `Accept: application/x-ndjson`、`X-Atoms-Task-Id`（本次新 UUID）。每行一个 UTF-8 JSON 事件：

- `step`：`event` 包含 `taskId/source/sequence/stepId/label/status/at/detail`。状态为 `started/completed/failed`。来源分别是 `server` 和 `browser`，各自单调序号及实际时钟；保存数组保持接收顺序，不假定两端时钟同步。
- `result`：匹配 `taskId`，包含结构检查后的 `result`（HTML、实际模型标识、耗时、时间）及 `assistantReply`（完整文本或 `null`）。
- `error`：匹配 `taskId` 及脱敏失败说明。流开始后失败通过此终态传输，HTTP 200 本身不表示生成成功。连接关闭但无完整终态、结果后异常、多终态、任务错配等均失败。

服务端在真正执行时发出请求准备、模型调用、提取产物、HTML 结构检查事件；上游等待期间可以读到调用开始。浏览器实际记录结果接收、项目事务、预览装配、iframe load、平台数据读写及脚本错误，不显示未执行的工具或测试。iframe load 仅说明载入，结构合格不等于业务验收。

首次模型请求要求一个 JSON 对象 `{ "html": "完整文档", "assistantReply": "面向用户的解释正文" }`，单次调用 DeepSeek V4-Flash。M2 沿用原 HTML-only prompt。首次 token 上限由 8192 调整到 12288，说明上限 32000 字符，HTML 上限 500000 字符；服务端 120 秒、浏览器 135 秒、函数上限 180 秒。HTML 或任务超过边界明确失败；正文超过限制则整段舍弃并在提取详情中明确原因，合格应用仍保留，不静默截断、不自动补调。不是模型 token 流。

有效 JSON 的正文缺失、非字符串、空白或超长，以及 HTML-only 响应，都以 `assistantReply: null` 降级；只有唯一完整且结构检查合格的 HTML 才保留。损坏 JSON、不完整 HTML、上游截断终态都失败。说明中的标签不会参与 HTML 提取；说明在 React 文本节点中完整呈现，不做 HTML 注入。浏览器兼容部署切换期间旧 JSON 响应，但不补造服务端事件或正文。

## 保存、恢复与失败

数据库名称、版本和源保持原样。`SavedProject.initialGeneration` 可选，包含任务 ID、真实开始时间、说明或缺失状态、事件。缺少字段的旧项目不显示虚构历史，不为恢复调用模型。

项目首次写入与已有说明/事件一起提交，成功后才能宣称项目已保存。后续预览和数据步骤以独立事务读取最新项目、核对任务 ID、按来源与序号去重追加；不把旧快照覆盖到项目，不改业务数据或更新时间。这样即使日志晚于数据保存或采用提交，也保留最新代码和数据。日志事务单独失败有明确提示，项目/业务数据已提交的结果仍可恢复。日志写入中显示状态并注册离开保护；写入未完成就强制关闭时，恢复仅展示实际保存的事件，缺少结束记录不会补造成功。

原始需求仍由项目保存；模型正文与平台执行事实分别展示。M2 开始后停止把新的预览动作归到首次任务；恢复只展示已保存的首次记录，不把本次重开伪装成首次生成活动。
