创建名为「工作台验收计数器」的极简中文前端应用，白底蓝色按钮。显示当前次数，显示元素 id=countValue，按钮文字“增加一次”，每次加1。使用 atoms.loadState()/atoms.saveState() 保存 {count:number}。旧数据不存在时默认为0，读取完成后启用按钮，不在初始化时保存默认值。每次点击等待保存并提示。不要外部依赖、登录或后端。助手说明已实现的交互和实际限制。

助手 首次生成

已完成「工作台验收计数器」：白底、蓝色按钮的极简中文页面。

已实现的交互：
- 页面显示标题、当前次数（元素 id 为 countValue，带 aria-live）与按钮“增加一次”。
- 启动时先禁用按钮，等待 atoms.loadState()：若无旧数据（返回 null）则默认 count=0 且不立即保存；若有合法 {count:number} 则恢复原值；读取完成后启用按钮。
- 点击按钮：同一事件处理器内先把 count 加 1 并渲染，随后立刻用完整快照 {count} 调用 atoms.saveState()，先显示“正在保存…”，保存 Promise 成功后才显示“已保存”，期间按钮保持禁用，不并发、不跳过保存。
- 失败处理：读取失败时显示错误并保持编辑停用；保存失败时显示错误并回滚计数，再允许重试。若已有数据格式无法识别，则不覆盖、保持只读并提示。
- 键盘可达：按钮为原生类型，Tab 聚焦、Enter/空格触发；带 focus-visible 焦点环；布局在窄屏下自适应。

使用方式：打开页面，等按钮变为可点击（蓝色），点击“增加一次”，看到状态提示“正在保存…”继而“已保存”。

实际限制（如实说明）：
- 数据仅保存于当前浏览器与当前站点的 atoms 存储中，无法跨浏览器、跨设备同步，清除站点数据会丢失记录。
- 无后端、无登录、无外部服务或网络请求，因此不存在云端备份或多人协作；也没有任何服务端校验。
- 恢复能力仅限本浏览器和本站点；若存储读取或写入失败，应用会显示错误并停用或回滚，不会伪造成功。
- 未实现、也不会模拟任何后端操作。

助手 本轮修改

本轮变化：

1. 新增「减少一次」按钮（id=subButton），点击后计数减 1，最低不会低于 0。减到 0 时该按钮自动禁用，避免出现负数。
2. 增加一次按钮（id=addButton）保持不变，仍为每次加 1。
3. 计数显示元素 id=countValue 保持不变，数据格式仍为 {count:number}，读取/保存仍完全通过 window.atoms.loadState() 与 window.atoms.saveState()。
4. 旧数据原样恢复：仅在 loadState 返回 null（新项目）时使用默认 {count:0}，初始化阶段不会写入默认值；若已存在但结构不可识别，则只读显示并提示，不覆盖。
5. 两个操作共用同一个异步变更处理器：先更新内存状态并渲染，随后在同一个事件处理器中同步调用 saveState（传入完整快照 {count:number}），等待其 resolve 后才显示「已保存」并重新启用按钮；失败时回滚到上一次的计数并显示错误。

使用方式：页面加载会先读取已保存数据，读取完成后按钮才可用；点击「增加一次」或「减少一次」，下方状态区会先显示「正在保存…」，保存成功后显示「已保存」。

实际限制：本应用没有后端、登录或外部服务，数据仅通过平台提供的 atoms 存储在当前浏览器与本站点中；恢复能力限于此浏览器与站点（站点数据被清除时数据会丢失）。保存失败（例如存储被拒）时会如实提示错误并回滚本次改动，需要用户重试。
