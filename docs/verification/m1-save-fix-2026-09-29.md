## 实际修改与取舍

目标是让同一预览内用户看到的已保存状态对应当前已接受的业务修改。采用 M1 明确允许的“保存期间禁止新修改”，不引入 revision 队列、后台重试或 M2。

1. `src/lib/preview-document.ts`：`saveState` 调用时同步设置 body 的 `inert`，并在 window 捕获阶段拦截点击、指针、键盘、输入、change 等编辑事件。捕获拦截也覆盖可能逃逸祖先 inert 的 modal dialog。锁定发生在发送 postMessage 之前，不依赖 React 或父窗口异步渲染。所有进行中的保存结束后恢复原 inert 状态和焦点；成功、失败、发送异常、超时路径均释放锁，应用的 await/catch 有机会先更新状态。
2. `src/app/api/generate/route.ts`：生成契约要求每次业务修改在同一事件处理函数中立即提交完整快照；禁止用定时器、防抖或保存中分支延后提交，禁止后台修改数据或绕过平台锁。保存成功才显示 saved，失败如实反馈。
3. `src/components/app-preview.tsx`：保存期间明确显示“应用数据正在保存…暂时无法编辑，完成后可继续”。原来的事务 complete 后确认机制保持。
4. `tests/browser/save-race.spec.ts`：使用未经修改的旧真实 HTML，保持真实事务直至测试主动释放；保存中尝试 click 和 Enter 不产生第二次修改，确认后立即提交下一项，在出现 saved 的事件上直接关闭；重开检查两项及生成请求计数。没有用增加等待或修改 HTML 掩盖原失败。
5. `tests/browser/persistence.spec.ts`：业务事务失败后补验解除编辑锁和输入仍可编辑。
6. `README.md`：说明即时保存契约、保存锁、旧项目注入更新方式与交互代价。
7. `eslint.config.mjs`：将 `docs/**/assets/**` 归档证据排除出源码 lint。原 review 的不可变 CJS 复现脚本导致现有 ESLint 的 no-require-imports 报错；保留原文件，而非为通过 lint 改写失败证据。产品源码和 tests 仍完整检查。

交互代价：保存期间的点击/按键不被接受或排队，用户在解除锁后继续操作；状态明确解释暂时无法编辑。它减少生成物自行维护 dirty/revision 的出错面，适合本次 M1。慢存储时编辑会暂停更久。

兼容性：原始 HTML 和 IndexedDB 名称、版本、结构不变。每次打开项目都会注入新桥接，旧项目无需重新生成；已打开的旧页面须重新打开才能加载修复。原始 HTML 单独搭配不具备锁的 mock API 仍可复现其旧逻辑问题，本次修复职责在平台注入接口；没有宣称改好了任意生成代码。若其他历史产物在首次调用 saveState 前就自行延迟或后台修改数据，本次锁无法发现这些未提交修改；已验收的原真实产物与本次新产物均已实测。
