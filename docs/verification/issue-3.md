## 失败与复验记录

1. 初次本地生产构建受沙箱端口限制而失败。以获得执行权限的 Node.js 24 直接调用 Next CLI 后构建通过，两次 Vercel 构建也通过。没有绕过编译错误或修改构建内容。
2. 第一版受控待办夹具使用 form submit，sandbox 未授权表单，因此按钮不触发提交。改为普通按钮点击，生成要求也明确不使用 form/submit。修正后 5 项保存恢复本地测试全部通过，保留脚本隔离边界。
3. 第一次完整线上回归有 1/10 失败：首次添加按钮点击后输入内容仍在、没有出现待办或保存请求。未认定为已定位的存储缺陷，也未加自动重试掩盖。单场景附 trace 连续 3 次通过；随后完整线上回归 10/10 通过。其偶发点击原因未确定，记录为测试稳定性观察，不声称已证明不存在此类问题。真实应用的实际操作与恢复独立通过。
4. 保存失败验收有意在 IDB request success 后中止 transaction，验证平台不会提前报成功。真实待办显示保存失败，刷新后故障注入的新条目不存在，之前的已完成条目完整保留。这是受控失败，不是一次自然线上丢数据事件。
