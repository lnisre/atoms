浏览器先通过生成 HTTP 入口取得签名票据，再用同源 WebSocket 保持同一执行实例。事件、心跳和 QA 回传都经过该连接；Vercel 的容器仍可伸缩，不能依赖两次公网 HTTP 命中同一个内存任务。每个 Python 进程只处理一个任务，原截止时间覆盖导入、角色、解析/传输重试和工具等待。程序不会发出第 21 次请求；达到 4 分钟、离开、连接中断或心跳失联时终止进程。已被服务商接受的请求不保证停止计费。

平台强制附加读取前禁用、读取失败保护、保存失败反馈、保存锁、合成数据保全检查。模型不能删除这些检查。QA 每次只规划一个冻结必检项，平台绑定场景和行身份并合并完整计划；业务操作提供固定启动/保存完成等待，保存中的平台检查仍立即执行。实际 QA 失败直接结束，不返工、不修改旧预期。模型计划语法纠正发生在工具执行前，并计入原预算。

首次成功同时保存项目、原始代码、实际角色交付、说明、调用记录和检查结果；后续日志沿用按任务读取最新状态再追加的事务。恢复不调用模型。M4 修改继续保留单模型、候选、试用和采用语义，并明确显示未执行四角色 QA；另有一次真实 M4 修改 HTTP 请求成功返回 `deepseek-flash` 结果。
