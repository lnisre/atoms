## 输出、归属和保存合同

追加修改与首次生成使用相同 NDJSON 协议、完整性校验与单次模型 JSON 输出（完整 HTML＋assistantReply），token 上限 12288。每次浏览器请求新建 taskId；服务端和浏览器各自记录真实顺序与时间，服务端不接受旧任务事件冒充本轮。原需求、完整基线 HTML、成功的本轮需求作为上下文；失败尝试不加入成功上下文，不替换有效候选。

`ModificationGeneration` 保存 projectId、taskId、本轮需求、startedAt、assistantReply、events 和 outcome。候选阶段只有内存记录，成功轮次保存需求/正文/日志，失败尝试随会话丢弃。预览录制回调绑定产出其 HTML 的候选任务；数据操作 stepId 包含实际通道，避免不同 iframe 的请求序号混合。副本准备、试用读写与正式读写准确区分，没有复制业务数据正文到日志。

采用事务读取最新项目，在一笔 `projects` 事务中替换最新 HTML 并追加修改记录，保留原始消息和所有已保存的修改消息。修改记录可选 `generations` 字段保存这次采用的成功轮次，`codeTaskId` 指向最新候选对应任务。消息不保存每轮 HTML，不建立代码历史。采用参数不包含试用数据，事务不写 applicationData。

采用完成仅在事务提交后记录，再以独立事务读取最新项目并追加对应任务事件；追加失败不否定已提交的代码/消息，而明确说明最新日志可能无法恢复。采用事务本身失败时旧结果仍可恢复、当前候选仍可手动重试。重开不会补造缺失的完成事件，未存下结束事件显示“未记录结束状态”。

放弃、刷新、关闭或离开项目时丢弃未采用需求/消息/试用数据，已保存记录不变。候选生命周期终止后录制回调失效；旧 iframe 通道无正式写入权限。恢复使用原库名/版本/源，不调用模型；下一次修改使用最新已采用代码。旧记录缺少 generations 或 initialGeneration 时不补正文、时间、日志，也不清空业务数据。

有效完整 HTML 缺正文明确降级，允许试用和采用；无效 HTML、错配任务或不完整传输失败，不补调模型。详情展开不参与 iframe key，不清空输入和试用副本。#18 负责完整工作台视觉与消息流统一，本任务先交付可操作的回复与执行详情。
