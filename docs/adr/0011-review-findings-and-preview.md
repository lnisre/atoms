# 审查问题与预览资格分离，重大问题最多两次整体返工

2026-10-01，用户反馈两次审查拒绝使新应用无法展示，要求非致命问题不能阻断 iframe，并在研究结论上明确将返工上限改为两次。新任务使用 atoms-team/3：重大/一般问题有精确代码引用和可达后果，approved 只表达无问题，不再决定交付。重大问题最多两次整体返工（首次加两次共三份代码）；一般问题直接交付。4 分钟、20 次请求和一次审查格式纠正继续共用，不重置预算。此决定替代 ADR 0006/0009/0010 中“无阻断意见才交付”及一次返工限制，历史证据不改写。

平台先验证每份完整代码的身份、交接与装配，再独立保留工件。正常结束、审查格式/服务失败或预算耗尽均可携带已完成工件；失败/超限仍如实记录，不补造角色成功。用户停止、错任务/代码、协议损坏和期限后新产物不能替换当前成果。浏览器只在收尾后显示代码；本轮不改为边生成边预览。

执行阻断由平台拥有，模型没有 fatal 开关。保留 HTML 装配、sandbox/CSP、来源/项目验证和平台数据保护；额外用语法树识别非常窄的顶层无条件空循环，普通功能缺陷和脚本异常不因此禁止展示。这不是通用恶意代码检测或资源隔离证明，复杂死循环仍是已有能力边界。

数据丢失/持久化缺陷可副本预览但不可采用；已有数据问题没有当前代码的明确修复记录时继续限制正式数据，不能靠换 hash 或审查失败洗掉。审查不可用且无已知数据风险可由用户明确采用。首次这类产物自动保存为待验证项目，试用数据仍只在会话中；普通无问题/非数据问题首次沿用自动保存与正式使用。修改始终需明确采用，采用只写代码及关联记录，最终版本决定采用资格，祖先轮次的真实失败和意见仍保存。

待验证代码存入新增 draftResult 字段，旧 result 字段只存无脚本说明页，避免旧客户端把未知模式的代码接到正式数据。新版恢复原代码和限制；明确使用/采用时原子移除 draftResult，保存正式代码。旧 v1 QA、v2 二值 Reviewer 和 M4 记录按原类型展示，不重新审查、不补造历史。

相关历史规格：#23、#25–#28。它们的归档不表示本轮策略或旧真实验收缺口已完成；新验收见 docs/verification/reviewer-preview-policy.md。
