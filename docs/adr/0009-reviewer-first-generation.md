# 首次四角色交付改为代码审查

用户在实际体验中反复遇到 QA 检查计划格式失败，决定先跑通四角色，并将 QA 改为 Reviewer。首次生成改为 Leader、Requirements、Engineer、Reviewer：Reviewer 对原始需求、冻结规格、实际 HTML 和平台约定进行静态审查，不再生成或执行浏览器检查计划。此决定替代 ADR 0008 中首次生成依赖完整浏览器 QA 的交付门槛，连接、隔离、预算和取消约定继续有效。

采用 `atoms-team/2` 区分新的审查交付与历史 QA 记录。审查结果绑定代码哈希，只有没有阻断问题、四角色已执行且任务正常退出才交付；审查拒绝仍终止，不通过重复审查获取通过。格式纠正最多一次，必须包含原输出和字段错误，计入原预算。原 QA 工具和历史证据保留；静态审查不能证明业务运行正确，界面、记录和验收报告必须明确这一限制。
