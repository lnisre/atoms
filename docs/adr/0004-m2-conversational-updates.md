# M2 对话修改先试用再采用，采用后回退留待后续

2026-09-29，用户确认 M2 的目标是在已有项目内通过对话持续修改应用。修改结果先作为候选版本使用数据副本试用，用户明确采用后才生效；采用前失败或放弃时，原应用与原数据保持可用。M2 衔接 M1 保存恢复验收完成后的版本，沿用既有技术栈、单文件 HTML、平台数据接口与同浏览器恢复范围。

## 已确认范围

- 用户在当前项目追加修改需求，系统结合已有需求和代码生成更新，不要求重新描述整个应用。
- 尚无候选版本时，以当前已采用的代码为修改基础；已有候选版本时，后续需求基于最新候选继续修改。用户可以多轮调整后一次采用，采用前原应用保持不变；放弃时丢弃本轮未采用的修改。
- 工作台围绕迭代流程完善：左侧查看需求与追加修改，右侧操作预览；清楚展示修改进度、修改结果及保存状态。精确视觉还原不作为本阶段门槛。
- 生成完成不等于替换当前版本。候选版本使用试用数据，用户点击“采用修改”后才成为项目当前使用的版本；试用不能直接写入原项目的业务数据。
- 采用修改只更新代码，继续使用原项目的业务数据；试用中的新增、删除和修改不写回。新代码从原项目数据开始运行，为新增字段提供合理默认值。
- 未采用的候选版本、试用数据及本轮对话仅保留在当前会话。刷新或关闭页面后恢复已采用且保存成功的应用；界面明确说明未采用结果会丢失，再次取得修改结果需要重新生成。
- 修改后原有业务数据保留，原有功能继续可用。首批支持增加字段、增加筛选和调整样式等兼容变化；旧记录缺少新增字段时采用合理默认值，不引入通用或破坏性数据迁移。
- 生成失败或用户放弃候选版本时，原应用和原业务数据保持可用。此处是采用前的保全，不要求实现采用后的代码回退、数据恢复或 Agent 清理。
- 采用后的应用和业务数据仍自动保存，同一浏览器重开后恢复最新已采用且保存成功的结果。
- 采用后保存本次采用对应的用户修改需求与简短结果记录，重开后恢复这些修改记录，帮助用户理解应用如何演变并继续修改。保存修改记录不要求保存每次生成的代码，也不提供采用后的回退。

## 范围调整与后续恢复原则

本次澄清替代了本记录较早的“保留上一份代码并允许采用后回退”方案。仅恢复旧代码无法保证后续写入仍兼容新数据；同时解决回退、数据变化和迁移会明显扩大 M2。当前投入集中在“追加需求 → 副本试用 → 采用或放弃”，完整历史列表、采用后回退、数据恢复和 Agent 清理留待后续阶段。

用户同时确认：未来需要恢复到确定的旧状态时，优先使用事先保存的代码与数据快照。Agent 可以辅助提出清理或迁移方案，不应依靠其推测来替代已有状态的精确恢复。这是后续设计原则，不要求 M2 建设项目快照系统。

本轮讨论已明确 M2 的范围与核心交互。本记录不表示功能已经实现，也不增加 M1 的验收要求；实际接口与内部状态组织应在实施规格中落实上述行为。
