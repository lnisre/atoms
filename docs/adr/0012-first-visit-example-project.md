## 已确认范围

- 每个本地工作区初始化一次。已有项目不覆盖、不自动追加；重复访问和模板升级不重置用户修改。项目及初始化标记需保持一致，失败不留下半份项目，也不误标完成。项目删除或清理后的语义由一次标记区分，本轮不顺带新增删除/模板管理功能。

- 示例准备失败不阻断首页：保留输入和已有项目，轻提示并允许重试。存储本身不可用要如实说明保存受影响；读库失败不能当作空工作区，也不能触发写入或标记初始化成功。
- 用户自己的项目 ID、代码与业务数据独立，示例来自固定包，不依赖每次首访访问原 Preview URL。示例后续操作、保存、候选试用和采用沿用现有规则；初始化不计作真实模型生成成功。

## 已确认的计时恢复规则

2026-10-02，用户确认示例按实际经过时间恢复当前计时段：运行一分钟后刷新，应显示约 24 分钟；关闭后重新打开，也按经过时间计算剩余时间。恢复时若当前一段已经到期，只结算这一段并暂停，不补算多轮专注；已暂停的计时保持暂停，重置回到初始专注计时的暂停状态。完成次数的处理继续区分专注与休息，不能因重复刷新而重复结算同一段。

实施可持久记录本段截止时间，页面重新打开时计算状态，无需后台服务或让关闭的页面继续执行。开始、暂停、重置与到期结算需遵守真实保存成功/失败和数据保全约定，不能依赖 beforeunload 一定成功写入。精确字段和恢复算法由实施确定，并用可控时间的实际运行检查验证。

原候选每秒只更新内存中的剩余时间，仅在开始/暂停/重置/阶段切换时保存。上述恢复政策是用户明确选择的行为调整；修订版应有自己的代码身份与验证记录，不声称与导出原候选逐字节相同。

## 工程边界与验收方向

- 原子初始化不预设数据库升级：新增元数据 store 或在现有 store 中以严格类型区分元记录均需评估读取过滤与兼容成本。不能把跨 IndexedDB/localStorage 的两次写入声称为同一事务；具体存储选择由实施确定并验证。
- “新工作区”按当前浏览器和站点本地范围判定，不识别自然人或增加账号。项目深链接保持原有恢复/缺失提示，不以示例偷偷替换缺失的目标项目；已有项目、初始化标记和存储错误分别处理。
- 同源并发首访不能创建重复副本；初始化后反复刷新、用户修改、模板更新都不重灌代码和数据。清除整站数据或换站点属于新的本地范围，不承诺跨环境识别原用户。
- 验收包括：全新工作区自动提供、已有用户保全、并发不重复、初始化失败可重试、真实计时与暂停/重置、运行中刷新/关闭恢复、跨到期仅结算一次、读写失败保护、对话修改与只采用代码、重开零模型调用。已保存历史数据与未知字段不能被示例初始化或计时修正清空。
- 不扩展模板市场、完整项目导入导出、新账号/同步、删除/重置示例管理或后台提醒；实现聚焦一份可靠素材和现有项目主链路。

## 实施选择

初始化标记放在现有 `applicationData` store 的保留键 `$atoms:workspace:first-visit`，不包含业务 `state`。项目仍只存在 `projects`，业务读取仍按独立 UUID；因此不升数据库版本，旧标签无需迁移或项目列表过滤。初始化事务同时锁定两个 store 并重新判断项目与标记，来源 null 不创建业务记录。标记不带模板版本，模板更新不会触发重新初始化。

示例 HTML 随 `public/examples/pomodoro-v1.html` 发布，创建入口只加载固定路径并校验固定 SHA-256，不接收外部代码、模型来源声明或审查意见。`exampleSource` 仅保留来源身份，后续候选的审查、数据隔离和采用资格仍由原有流程决定。
