# 首次四角色任务由一条连接绑定原生团队执行实例

首次生成的 QA 交付门槛已由 [ADR 0009](0009-reviewer-first-generation.md) 替代；下文保留原决策背景。

#25 在 Next.js 容器内监督每任务独立的 Python 3.11 子进程，保留固定 MetaGPT SHA 的 Team、MGXEnv、Role、RoleZero 与 TeamLeader 循环。受限 Action 只开放规格、单文件 HTML、浏览器检查和交付决定。调度核心未修改；依赖修正仅 LanceDB 可选化与已验证的 PyArrow 14.0.2 基线。

浏览器先通过生成 HTTP 入口取得有期限的签名任务票据，再打开同源 WebSocket。该连接承载角色事件、QA 请求、工具反馈和心跳；容器网关将其转发给同一 Next 进程。Vercel 容器仍是可伸缩的函数，分开的公网 HTTP 请求不保证命中挂起任务所在实例；[单条 WebSocket 固定到一个实例](https://vercel.com/docs/functions/websockets)，因此不引入分布式队列或持久任务存储。新的连接不恢复原任务，不重新设置原截止时间。#24 的无状态资格接口继续保持独立，不负责挂起团队。

浏览器关闭连接、请求取消、15 秒心跳失联、4 分钟截止或协议错误时，监督器终止子进程；所有角色的显式模型请求统一计数，最多 20 次。模型服务已接受请求的计费不保证能取消。启动导入、工具等待和收尾都计入原截止时间。成果只在当前代码全部检查通过、QA 模型判读通过、Leader 决定交付且进程正常退出后交付。

检查计划由冻结需求与 QA 业务场景组成，平台强制追加读取前禁用、读取失败保护、保存失败反馈、保存锁和合成数据保全检查。检查仍在独立 opaque-origin iframe 内执行，沿用 ADR 0007 的合成事件和共享 realm 限制。外部来源先由网关验证，再转换为内部 Next 来源；模型密钥只传给可信 Python 进程，任务票据和检查请求不含密钥。

首次成功沿用项目事务保存并附带真实团队/检查记录，日志继续使用按任务合并的追加事务。未迁移的修改仍用 M4 协议，明确显示未运行四角色 QA。第一次 QA 失败即结束；自动返工、完整停止与澄清体验及连续修改迁移不属于 #25。

需求角色冻结业务条件和数据合同，不提前猜测浏览器探针。QA 根据实际 HTML 选择合成数据与一次写入操作，再逐项规划业务检查。任务、代码和检查行身份由平台绑定；模型决定操作和业务预期。探针与全部计划在实际执行前冻结，固定平台门槛不受模型改动，失败后不改写计划达标。
