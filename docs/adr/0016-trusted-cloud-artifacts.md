# 云端代码提交同时验证用户身份与任务产物证明

#68 使用普通 CloudBase 用户令牌访问 PostgreSQL；团队执行器为服务端实际得到的终态代码、审查策略、需求和执行记录签发 HMAC 证明。数据库同时校验证明中的账号、项目、已领取任务、基础代码与版本，再提交首次成果或明确采用。这样普通用户直接调用公开 RPC 也不能伪造审查或解除限制，应用运行时无需数据库管理身份。

证明密钥 `ATOMS_ARTIFACT_SECRET` 与登录 Cookie 密钥独立，由迁移安装在无普通用户权限的私有表中，仅可信应用服务持有相同值。证明可以随产物返回浏览器，但不授予身份；所有提交仍需重新验证当前普通用户。密钥不进入模型、HTML、日志或下载。选择 HMAC 是为了使用现有 PG 内置 SHA-256 和普通用户 RPC，无需额外服务角色或新增持久任务执行服务；代价是部署和迁移必须同步管理此专用密钥。首次配置失败时拒绝启动生成；生产轮换须另外设计，不可直接替换数据库密钥使在途证明失效。

已启动任务的领取记录用于跨实例防重复付费，不是任务恢复队列。浏览器自然失效后原连接可按原预算收尾；保存仍需同账号重新认证。刷新、关闭或主动退出不提供任务接续。未采用候选和试用数据只保留在页面；候选链证明带真实成功轮次记录，业务数据不进入生成输入。旧 M2 任意 `baseHtml` 直通模型路径已撤下，兼容 `/api/generate` 入口也走同一账号/项目/任务协议，旧客户端需要刷新。

首次保存和采用在同一事务中写代码及对应记录，修改保留正式业务数据；待验证代码仍使用 `draftResult` 防止旧客户端连接正式数据。提交完成后的平台步骤另发签名日志，以任务和 source/sequence 追加到最新记录，不覆盖代码、数据或版本；日志失败与代码提交状态分别展示。
