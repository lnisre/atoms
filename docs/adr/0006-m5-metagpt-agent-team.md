# M5 复用 MetaGPT 四角色并采用 Reviewer 代码审查与有限返工

实施规格：[M5：MetaGPT 四角色团队、代码审查与有限修复（Issue #23）](https://github.com/lnisre/atoms/issues/23)。

2026-09-30 确认的 M5 使用 Python 承载 MetaGPT 四角色协作。2026-10-01，用户在实际体验中遇到 QA 计划与工具协议不稳定，明确将 QA 改为 Reviewer，并要求主规格和后续任务统一口径。当前团队为 TeamLeader、Requirements、Engineer、Reviewer，优先复用原生调度与角色循环，通过受限角色及平台适配接入。引入 Python 增加依赖与部署维护成本，但可以复用已有协作机制；不因业务适配需要就重写核心。

## 当前决定

- **应用范围**：继续生成单文件 HTML 轻量前端应用，沿用现有数据接口、隔离预览、固定访问源、同浏览器保存恢复和桌面工作台，不开放多文件构建、任意后端或自由终端。
- **四角色**：Leader 实际分派和组织交付；Requirements 冻结功能、约束和验收条件；Engineer 交付完整代码与说明；Reviewer 独立审查原需求、规格、实际代码及准确的平台保障。程序强制任务归属、完整性、运行上限及交付条件。
- **审查标准**：只以具体代码和可达行为支持的核心功能遗漏、错误行为、数据丢失或平台约定违例作为阻断问题；纯风格偏好或平台保障已排除的推测不作为阻断项。结果包括通过与否、摘要和阻断意见，绑定当前代码；无阻断问题才通过。
- **证据边界**：Reviewer 做静态代码审查，不生成或执行浏览器 QA 计划，不声称运行测试或所有业务功能已验证。现有平台保护、开发期浏览器回归和目标部署真实操作/保存/恢复验收仍必须执行，并分别记录来源。
- **交付与返工**：#25 首次审查拒绝即结束；#26 增加 Reviewer 阻断意见 → Leader 分派 → Engineer 修复 → Reviewer 复审新代码 → 无阻断才交付。最多一次整体返工，可同时修复多个问题；旧批准不能套给新代码，不能改规格或重复审查刷通过。复审仍拒绝则保全已有成果并结束。
- **格式纠正**：Reviewer 输出格式错误由其自身最多纠正一次，带回原输出和具体字段错误，计入原模型请求预算；它不是 Engineer 代码返工。无有效审查结果、传输或模型执行失败与有依据的代码拒绝分别处理。
- **预算与停止**：每任务初始最多 4 分钟、20 次模型请求、一次整体返工；角色切换、格式纠正、返工和复审不重置计数或截止时间。提供停止任务，离开后停止后续步骤并尽力取消在途执行，无后台续跑，不保证供应商已接受的请求停止计费。
- **澄清**：普通细节合理默认，关键功能/数据歧义集中提问并结束本轮，会话保留需求和问题；用户补充后重新发起，原成果不变。超范围需求说明限制及可行调整。
- **数据与采用**：模型不接收真实业务记录；独立测试使用合成数据，用户试用使用浏览器内真实数据副本。首次成功自动保存；修改基于最新候选，否则基于已采用代码，审查通过后供试用并由用户明确采用。采用只更新代码及对应记录，不写回试用或测试数据。
- **记录与展示**：M4 工作台展示实际角色、代码审查、阻断意见和返工过程，长规格/意见可展开。保存对应成功任务和采用记录，未采用内容仍限于会话；恢复不调用模型补造历史。旧 QA 与新代码审查保留真实类型，不互相改标。

## 原方案与保留事实

原 2026-09-30 方案要求 QA 生成计划并在独立页面执行。原型确实跑通过真实浏览器检查与模型修复，但也漏掉读取失败保护；这些历史实验及 [#25 的后续失败记录](../verification/issue-25.md)保留，不改写为 Reviewer 成果。

[#24](https://github.com/lnisre/atoms/issues/24) 已完成浏览器 QA 工具资格验证，所选独立 iframe 和合成数据通路可继续用于开发验证，保留隔离限制。它不再是每次 M5 生成必须调用的工具，浏览器执行位置选型也不再是 Reviewer 主链路的前置门槛。以后若恢复自动 QA，应另行记录新决策。

本决定替代本 ADR 原先自动 QA 的角色、运行时检查与交付门槛；同样收敛了实现侧更早的自动 QA 门槛。M1–M4 的历史范围保持原意，平台数据保护和独立运行验收没有取消。静态审查稳定性改善与真实运行质量是两个不同结论，不据少量样本承诺通用正确性。
