## Spec

原位置为旧真实 HTML 的 `isSaving` 定时器分支和旧请求完成即显示 saved。修复没有手改该 HTML，而是由当前平台在 `saveState` 发送 postMessage 前同步锁住交互（`preview-document.ts:35–36`），同时通过 body.inert 和 window 捕获监听阻止新编辑（第 11–23 行）。旧产物第一次修改立即调用 API，所以保存中的第二次用户操作不再进入那个定时器分支。

2. 释放事务，解锁后提交第二条；在应用“已保存”文本变化事件上立即关闭页面。

### 保护边界

锁只能保护已经进入保存 API 的修改，无法探知任意历史生成代码在首次调用前自行延迟或后台修改的数据。此限制不等于原 P1 未修复，也不自动成为新 M1 缺陷：M1 已规定生成应用必须遵守固定数据接口，本次原始验收产物和新产物均实测通过。若后续真实生成违反即时保存契约，应作为该生成失败记录，不能宣称锁提供任意代码正确性保证。

不要求增加 revision 队列、跨标签冲突控制、复杂重试或完整版本管理。保存中暂时不能编辑是此次修复的明确交互代价，状态反馈与 README 均已说明。
