# Atoms Demo

输入自然语言需求，通过 DeepSeek 官方 API 生成轻量前端应用，在隔离预览里实际操作。

当前实现覆盖 [Issue #6](https://github.com/lnisre/atoms/issues/6) 的明确采用、修改记录与恢复，以及 [Issue #5](https://github.com/lnisre/atoms/issues/5) 的会话内多轮候选与隔离试用，以及 [Issue #2](https://github.com/lnisre/atoms/issues/2) 的真实生成与预览，以及 [Issue #3](https://github.com/lnisre/atoms/issues/3) 的自动保存与同浏览器恢复。生成完成后保存项目需求和 HTML；应用操作通过平台数据接口写入 IndexedDB。首页的“已有项目”可重开保存的应用，不重新调用模型。

生产地址：[Atoms Demo](https://v0-test0-nine.vercel.app)。线上验证结果见 [#2 记录](docs/verification/issue-2.md) 、[#3 记录](docs/verification/issue-3.md) 、[#5 记录](docs/verification/issue-5.md) 与 [#6 记录](docs/verification/issue-6.md)。

## 运行

使用 Node.js 24.x、pnpm 10.12.1。已有 `.nvmrc`、`.node-version` 和 `engines.node` 约束版本；macOS Homebrew 可执行：

```bash
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
pnpm install --frozen-lockfile
cp .env.example .env.local
# 在 .env.local 填入 DEEPSEEK_API_KEY，不要使用 NEXT_PUBLIC_ 前缀
pnpm dev
```

打开 http://localhost:3000。未配置密钥时首页仍可访问，生成会明确失败，不返回预置应用。生产启动使用 `pnpm build && pnpm start`。

## 模型与运行边界

- `POST /api/generate` 接收 `{ "requirement": "应用需求" }`，限制 1–4000 字。Next.js Route Handler 使用 Node.js 运行时，仅从服务端环境变量读取 `DEEPSEEK_API_KEY`。
- 官方端点为 `https://api.deepseek.com/chat/completions`。请求模型 `deepseek-v4-flash`，使用 `thinking: { type: "disabled" }`、模型非流式返回；首次生成 `max_tokens: 12288`，M2 修改仍为 `8192`。官方响应标识为 `deepseek-flash`；界面如实显示，不把别名解释为固定模型版本保证。
- 首次生成用 NDJSON 实时传递实际平台步骤和最终产物，正文完成后整体展示，不要求 token 流。最终产物包含完整助手说明或明确缺失状态，以及 `html`、`model`、`durationMs`、`generatedAt`。耗时覆盖模型请求及解析，不包括浏览器网络和预览加载；不是未来耗时承诺。
- 首次模型响应为 `{ html, assistantReply }`，完整说明以安全文本呈现。HTML 通过唯一完整文档和结构检查后才运行。说明缺失或无效但 HTML 合格时保留应用，提示“本次未取得助手说明”，不会补调模型。HTML-only 输出按缺失说明降级；M2 修改仍仅提取 HTML。截断、损坏 JSON 和不完整结构明确失败，不自动修复、不用模板替代。
- 模型请求在 120 秒超时，浏览器在 135 秒停止等待；Vercel 函数 `maxDuration` 为 180 秒，需启用 Fluid compute。失败后由用户手动重新发起。
- 生成物为内含 CSS 和原生 JavaScript 的单文件 HTML，通过 `srcdoc` 放入 `sandbox="allow-scripts"` iframe。没有 `allow-same-origin`，不直接插入平台 DOM。
- 预览注入 CSP，禁止外部依赖、网络请求、嵌套页面及表单导航，只允许内联脚本、样式和数据图片。脚本运行错误可提示重新生成；加载成功不代表业务功能正确。沙箱限制权限，但不保证任意生成代码没有逻辑错误或性能问题。
- 生成应用使用平台注入的 `window.atoms.loadState()` 和 `window.atoms.saveState(data)`，不直接访问浏览器存储。没有账号、后台任务、版本历史、自动修复或跨设备恢复。隔离环境不允许表单提交，应使用普通按钮点击与键盘事件。
- 浏览器提交的原需求、本次修改、基础 HTML 和本轮成功修改需求会发送给 DeepSeek；平台不附带业务数据副本。模型密钥不进入浏览器 bundle、生成物或日志；上游错误正文不回传。公开无账号演示接口会消耗维护者模型额度，目前未实现账户配额或持久化限流。

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Vercel 函数时限](https://vercel.com/docs/functions/configuring-functions/duration)。

## Vercel 部署

在对应 Vercel 项目配置生产环境变量 `DEEPSEEK_API_KEY`，选择 Next.js 和 Node.js 24.x，启用 Fluid compute。通过 Vercel CLI 链接该项目，再执行 `vercel --prod`。后续更新继续部署同一项目和固定生产域名，保持 IndexedDB 的同源存储入口。修改数据库或接口时须保持已有数据和保存 HTML 的兼容性，不能通过改库名或清库完成升级。

`.vercelignore` 排除私人研究资料、北极星、本地凭据、环境文件及测试产物；不要上传整个工作区归档。`.vercel` 保存本机项目链接信息，按 `.gitignore` 排除。

## 自动保存与恢复约定

- 项目包含稳定 UUID、完整需求、列表标题、更新时间及当前 HTML/生成元信息；业务数据单独保存，并关联项目 UUID。M1 仅保存当前代码，没有历史版本。
- 数据库 `atoms-projects` 版本 1，`projects` 与 `applicationData` 两个 store。部署更新不改变名称、版本和数据格式。业务数据保存与项目更新时间在同一事务提交；只有事务 `complete` 后才显示保存成功。
- 注入脚本在生成代码之前提供 `window.atoms`。`loadState(): Promise<JSON | null>` 读取已有状态，新项目返回 null；`saveState(data): Promise<void>` 保存完整 JSON 快照（序列化长度最多 1,000,000 字符），成功后 resolve，失败时 reject。模型需先成功读取再允许修改，在每次添加、完成、删除后保存，不能将读取失败视为空数据。
- 应用调用经 `postMessage` 传给父页面。父页面检查当前 iframe 的 `contentWindow`、opaque origin 和每次预览的随机 channel；项目身份由父页面闭包绑定，消息不能指定其他项目。子页面也检查父窗口、平台 origin 和 channel。发送至 opaque iframe 的回复使用 `*`，同时严格限制目标窗口与 channel。
- 每次用户修改必须在同一事件处理函数中立即提交完整快照，不能用定时器、防抖或 isSaving 分支推迟保存。`saveState` 在调用时同步将预览设为 inert 并拦截编辑事件，直到保存成功或失败才恢复交互；平台同时显示“暂时无法编辑”。保存期间点击或按键不会产生新修改，需在恢复交互后继续。生成代码不得用后台回调修改业务数据或绕过锁。
- 新接口在每次打开项目时注入，已保存的旧 HTML 也获得上述保存锁，无需重新生成或迁移数据；已打开的旧页面需重新打开才能使用更新。它保护遵守即时保存接口的应用，不会自动修复任意生成代码的其他逻辑错误。
- 同一预览内读写按到达顺序执行，防止快速连续操作倒序保存；没有跨标签页冲突协调。多标签同时编辑同一项目时，最后提交的完整快照覆盖之前的内容。
- 项目保存与应用数据保存分别反馈。存储不可用、配额不足或事务中止时明确提示保留页面并检查权限/空间，不自动重试、不用内存结果冒充保存成功。重新生成预览使用新项目标识，保留此前已保存项目，避免新代码误读旧数据。
- 刷新使用 URL 的 `?project=<UUID>` 读取已有项目；关闭后重开首页可从项目列表进入。URL 只是本地记录的标识，复制链接不会把项目传给其他浏览器。
- 恢复要求同一浏览器配置文件、同一平台源（协议、主机、端口）且站点数据仍存在。清除数据、结束无痕会话、存储回收或更换浏览器/设备后不承诺找回。没有服务端备份，浏览器事务提交也不等于独立备份或断电耐久性保证。


## 多轮候选与隔离试用（Issue #5）

打开已有项目，在左侧“追加修改需求”填写变化并点击“生成候选”。没有候选时以已采用 HTML 为基础；已有候选时基于最新候选继续，保留本轮成功修改需求作为上下文。失败会结束等待，输入和已有候选保留，可手动再次点击生成。

右侧“候选试用 · 未采用”使用正式业务数据的副本。第一次候选生成成功后读取已提交的业务数据；读取失败则明确失败，不能当作空数据继续试用。后续候选继续使用本轮试用副本。`window.atoms` 接口保持不变，由父页面绑定项目与数据用途；试用更新只写内存，不写 IndexedDB，也不创建另一个正式项目。平台的“试用数据已更新”不表示正式保存。

候选 HTML、试用增删改与本轮对话不持久化。点击“放弃本轮修改”、离开项目、刷新或关闭后，重新打开仍使用已采用且保存成功的代码和正式数据。点击“采用修改”会把最新候选代码和本轮成功修改需求、简短采用结果记录一并保存到原项目；只有事务完成才显示已采用并保存。新预览重新读取正式数据，试用中的新增、删除、完成状态和字段修改均不写回。新增字段的兼容默认值由生成代码实现，需实际试用确认。

修改接口仍为 `POST /api/generate`，请求为 `{ requirement, modification, baseHtml, context }`；`context` 是本轮成功修改需求的字符串数组。原需求与本次修改各限 4000 字符，基础 HTML 最多 500000 字符，上下文 JSON 最多 32000 字符，请求序列化最多 3300000 字符。超限明确拒绝，不静默截断。首次生成继续使用 `{ requirement }`。

新增回归验证完整基础代码传递、最新候选选择、同项目标识、多轮试用数据延续、正式数据保全、失效通道、复制读取失败、生成失败与超时、放弃/刷新/重开清理。实际进展、失败和部署证据见 [Issue #5 验证记录](docs/verification/issue-5.md)。

## 明确采用与修改记录（Issue #6）

采用后，左侧“已采用修改记录”展示每次采用对应的多轮需求、采用时间和简短结果。下一次修改从刚采用的代码开始，放弃或刷新未采用结果不影响已有记录。旧 M1 项目缺少 `modificationRecords` 时视为暂无记录，不清库或改变存储入口。

代码与记录在原 `projects` 记录的一笔事务中提交；采用接口不接收试用数据，也不写 `applicationData`。采用保存失败会明确提示，并保留当前会话候选，原先保存的应用、记录与正式数据仍可恢复；检查存储权限或空间后可手动再次点击采用。保存期间暂停生成、放弃与项目切换，不加入后台重试。

采用成功后重新挂载 iframe 并生成新通道，旧试用消息不能获得正式写入权限。正式业务操作仍通过原平台接口自动保存。等待成功后刷新、完整关闭浏览器再用原配置重开，或从首页进入项目，恢复代码、正式数据和记录，无需模型调用。同源兼容重新部署也按此规则恢复。

不保存每轮历史代码，不提供采用后撤销、回退、快照或试用数据合并。生成成功和采用成功均不保证模型业务逻辑正确。检查与线上真实验收见 [Issue #6 验证记录](docs/verification/issue-6.md)。

## 阅读记录真实验收（M3 / Issue #11）

在[固定生产地址](https://v0-test0-nine.vercel.app)使用独立持久化浏览器配置，描述一个含书名、阅读状态、添加和删除的应用。真实生成后添加两条可辨认记录、修改状态，等待“应用数据已保存”后刷新检查；再在同一项目追加评分和状态/评分筛选需求。旧记录应显示合理的未评分缺省值，实际检查新旧功能后，在候选中做可识别的试用增删改。

采用并保存后，确认原记录保留、试用增删改没有写回，再在正式应用设置评分或状态并检查筛选。保存成功后刷新、完整关闭浏览器，再以同一配置从首页项目列表重开，检查代码、业务数据及修改记录恢复，Network 中没有新增 `/api/generate` 请求。不要清除站点数据或用临时无痕会话承担这一步。

本次两次真实模型调用完成闭环。首次产物恢复后旧记录控件禁用，通过现有追加修改路径由模型修复后复验通过；没有改写最终 HTML、修改平台代码或重新部署。完整需求、原始产物、隔离/采用/恢复结果、桌面截图、失败及请求计数见 [Issue #11 验证记录](docs/verification/issue-11.md)。


## 首页与项目入口（M4 / Issue #15）

首页使用固定侧栏、居中输入卡与项目卡片。点击示例只填入需求，点击向上箭头“开始生成”才创建应用；“我的项目”和最近项目可重开当前浏览器保存的应用。切换首页与项目网格保留未提交输入，不调用模型。工作台返回此前入口区域，候选离开和保存恢复规则沿用 M2/M3。

灰色参照控件明确禁用，尚不提供账号、多工作区、积分、资源、附件、语音或外部连接等能力。头像为独立装饰；封面为明确占位，不为缩略图运行项目。截图、视觉参数依据、未补齐的原站参照及生产验收状态见 [Issue #15 验证记录](docs/verification/issue-15.md)。

## 首次助手回复与平台执行记录（M4 / Issue #16）

首次生成时能实时查看服务端实际准备、模型调用、产物提取和 HTML 结构检查，随后查看浏览器的项目保存、预览装配/载入及数据读写。正文完整保留，步骤详情可展开；结构合格、预览载入和实际业务验证是不同结论。

首次回复与记录随项目保存，刷新及同浏览器重开不会再次调用模型。等待项目、应用数据和执行记录的保存完成后再离开；后续日志写入仅追加到对应任务，不覆盖新代码或业务数据。旧项目没有的正文、时间和记录不补造。修改路径现已复用同次输出与事件协议，详见下节。

[协议、失败与真实线上验收](docs/verification/issue-16.md)包含单次模型输出、22 条真实执行事件、保存恢复、缺失说明降级和首次线上请求代理错误的修复记录。


## 多轮回复与采用后恢复（M4 / Issue #17）

每次追加需求通过同一次模型请求取得完整 HTML 和助手说明。候选的需求、回复及平台执行记录仅留在会话；连续修改基于最新候选并沿用试用副本。后续失败保留已有候选，失败尝试不进入成功上下文。放弃、离开、刷新或关闭丢弃未采用消息；不会更新已保存项目。

采用时在同一项目事务保存最新候选代码、成功轮次的需求/回复/记录和修改摘要，保留此前首次生成与已采用消息，不保存中间 HTML。每个新消息关联项目 ID 与任务 ID，修改记录的 `codeTaskId` 标识最新代码对应的任务；`generations` 是可选消息字段，旧项目缺字段不补造。完成事件只在事务提交后追加；追加失败会单独提示，已经提交的采用仍有效，重开只展示实际保存的步骤。

试用读写明确标注会话副本；采用不接收试用数据，也不写正式业务数据。采用事务失败时保留旧保存结果与当前候选，可手动重试。恢复代码、正式数据和已保存消息不调用模型，下一轮基于最新已采用代码。完整 HTML 缺正文时显示“本次未取得助手说明”并允许试用/采用，无效 HTML 仍失败，不自动补调。

[保存合同与验收证据](docs/verification/issue-17.md)。工作台完整视觉和消息流统一由 #18 负责。

## 桌面工作台（M4 / Issue #18）

工作台使用与首页一致的中文浅色视觉参数、紧凑项目栏和双层预览工具。消息按已知先后顺序排列，最新在底部；上翻阅读不会被新执行事件拉回，可点击“回到最新消息”。助手正文、平台执行记录和结果卡分别标明来源与状态，详情展开不重新生成或重置预览。旧记录缺少内容时不补造历史。

底部输入与候选旁的采用/放弃保持可达；正式保存和试用边界持续显示。灰色工具入口当前未提供，不能触发发布、模型或历史回退。项目封面仍是占位。[对照依据、实际验收与剩余参照缺口](docs/verification/issue-18.md)；功能通过不代表所有高还原条件完成。
