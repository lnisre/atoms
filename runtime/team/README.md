# M5 bounded native team runtime

The product entry point remains the existing homepage and `/api/generate`. Generation and modification negotiate `atoms-team/2` and uses a pinned same-origin WebSocket; both use the same bounded native team. A browser refresh only restores IndexedDB, never starts a model task.

The Python adapter uses `FoundationAgents/MetaGPT@11cdf466d042aece04fc6cfd13b28e1a70341b1f`. `BoundedLeader` selects the existing fixed-SOP Action extension; all run/observe/think/act/react/publication implementations are inherited. Each worker is a native Role with a distinct Action and observed leader message. Gateway requests go only to `https://api.deepseek.com/chat/completions`, model `deepseek-flash`, JSON output mode, no SDK retries. A connection interruption may retry once; the failed request remains counted with unknown usage. Reviewer output format may be corrected once with the previous response and field-level errors; the first valid rejection returns to Leader for at most one whole-code repair and a review of the new code; a second rejection ends the task. Reviewer JSON and field errors share one correction across the entire task; transport failures do not trigger code repair. Every request is counted before send; response ID/model/usage and elapsed time are recorded. The response alias is not an immutable model checkpoint.

`optional-lancedb.patch` changes packaging only; `requirements.lock` pins the Linux versions reconstructed from the earlier verified environment. Docker rebuilds public upstream with these pins because the Atoms project's build identity cannot pull the other test project's private image. Target `pip check` and native-loop tests are build gates. The MIT upstream license is included. No default arbitrary shell, dependency installer, free tool planner, or upstream code-writing agent is exposed.

For local execution, use Python 3.11 and install patched upstream plus `requirements.lock` in an isolated virtual environment. Point `METAGPT_PROJECT_ROOT` at the upstream checkout with the provided offline `config2.yaml`; set `ATOMS_TEAM_PYTHON` to that environment's Python. Put `DEEPSEEK_API_KEY` and a random `QA_TOOL_SIGNING_KEY` only in the trusted process environment. Never use `NEXT_PUBLIC_`. Build with `pnpm team:build`, then run `node --env-file=.env.local runtime/team/gateway.mjs`. Default gateway port is 3105; its internal Next server uses port+1 bound to loopback. `next dev`/`next start` alone do not supply the first-generation socket gateway. Docker supplies the gateway and Python environment automatically.

The gateway validates public Origin before proxying to Next's internal localhost origin. Its process-local internal capability is stripped from incoming public requests and is never sent to the browser. HTTP task tickets preserve the original start time; the socket owns the live task. No reconnect or background recovery is implemented. One task has 240 seconds and 20 model requests across all roles; disconnect cancels the request and kills the Python process, with a 15-second heartbeat backstop. At most two tasks occupy one worker. This is not an account-wide distributed quota.

Requirements freeze business criteria and the data contract. Engineer implements the full HTML and, only after a current-code rejection and actual Leader delegation, may deliver one repaired artifact. Reviewer receives the original request, full specification, actual HTML and the same platform contract; it returns only approved, summary and blocking issues using `review.schema.json`. Approval with nonempty issues is invalid. The platform binds task and code identities, validates actual Leader/worker handoff order, invalidates approval on code change, requires completed calls for every delivery, and waits for clean process completion before delivery. Records retain every rejection, decision and modification explanation, while full old HTML stays only in the live executor for repair. This is static code review, not browser or business acceptance. The first-generation path does not request test plans or run model-authored QA. The existing standalone `/qa` tool and historical `atoms-team/1` check records remain available; new generation explicitly rejects obsolete protocol requests before model invocation. Four-minute/20-call limits, cancellation, isolation, persistence and M4 behavior remain in force.

Tests:

- `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`.
- `METAGPT_PROJECT_ROOT=... <venv>/bin/python runtime/team/test_runner.py`: zero-network native routing, exhausted budget, deadline and cancellation.
- `tests/team/fixture_transport.py`: explicitly scripted provider, never a real model. A test-only launcher can invoke it with `runner.py`; use `DEEPSEEK_API_KEY=offline-test-placeholder` and `TEAM_FIXTURE=1` for `tests/browser/team.spec.ts`.
- Existing UI/storage regressions use `team-fixture.ts` with explicitly synthetic review and role records. They do not provide real model review evidence.

Actual provider runs, target deployments and all failed attempts are recorded separately in `docs/verification/issue-25.md`.

Stop closes the task connection and kills the supervised process; the page ends waiting immediately and rejects late results. Requirements may return collected clarification questions or an unsupported limitation with a feasible alternative; these end execution rather than wait server-side. A user supplement starts a new task and preserves earlier questions in the current page session. Explicit terminal outcomes are passed, rejected, failed, stopped, limit, clarification and unsupported. Modifications include full baseHtml and successful requirement context, never business records; candidate adoption binds the latest successful task to the code hash.
