# M5 bounded native team runtime

The product entry point remains the existing homepage and `/api/generate`. Generation and modification negotiate `atoms-team/3` and uses a pinned same-origin WebSocket; both use the same bounded native team. A browser refresh only restores IndexedDB, never starts a model task.

The Python adapter retains `FoundationAgents/MetaGPT@11cdf466d042aece04fc6cfd13b28e1a70341b1f` native Team/MGXEnv scheduling and the bounded deepseek-flash HTTP transport; upstream run/observe/think/act/react/publication implementations remain inherited. New tasks use `atoms-team/3`. Reviewer reports major/minor findings with exact code quotes, triggers and consequences, plus evidence for resolved prior findings. Approval means no findings, not permission to preview. Major findings allow at most two whole-code repairs (three implementations), minor findings finish directly. Format correction is still once per task. All work shares 240 seconds and 20 requests; no extra model call is required to preserve a completed artifact after failure or timeout.

`optional-lancedb.patch` changes packaging only; `requirements.lock` pins the Linux versions reconstructed from the earlier verified environment. Docker rebuilds public upstream with these pins because the Atoms project's build identity cannot pull the other test project's private image. Target `pip check` and native-loop tests are build gates. The MIT upstream license is included. No default arbitrary shell, dependency installer, free tool planner, or upstream code-writing agent is exposed.

For local execution, use Python 3.11 and install patched upstream plus `requirements.lock` in an isolated virtual environment. Point `METAGPT_PROJECT_ROOT` at the upstream checkout with the provided offline `config2.yaml`; set `ATOMS_TEAM_PYTHON` to that environment's Python. Put `DEEPSEEK_API_KEY`, `QA_TOOL_SIGNING_KEY` and the migration-installed `ATOMS_ARTIFACT_SECRET` only in the trusted process environment. Account Auth/PG configuration is also required; see `docs/verification/issue-68.md`. Never use `NEXT_PUBLIC_`. Build with `pnpm team:build`, then run `node --env-file=.env.local runtime/team/gateway.mjs`. Default gateway port is 3105; its internal Next server uses port+1 bound to loopback. `next dev`/`next start` alone do not supply the first-generation socket gateway. Docker supplies the gateway and Python environment automatically.

The gateway validates public Origin before proxying to Next's internal localhost origin. Its process-local internal capability is stripped from incoming public requests and is never sent to the browser. HTTP task tickets preserve the original start time; the socket owns the live task. No reconnect or background recovery is implemented. One task has 240 seconds and 20 model requests across all roles; disconnect cancels the request and kills the Python process, with a 15-second heartbeat backstop. At most two tasks occupy one worker. This is not an account-wide distributed quota.

Requirements freeze business criteria. The platform verifies every artifact's task/project/base identity, hash, HTML injection point and actual role handoffs before caching it. The server streams a complete artifact checkpoint independently of final review; clients publish it on an honest terminal outcome, including review failure or budget exhaustion. Cancellation, invalid identity/protocol and late artifacts do not publish. Preview uses platform policy, not model severity alone. A narrow parsed-JS empty-loop rule supplements existing isolation; this does not provide general nontermination or malicious-code detection.

Data/persistence findings permit trial preview but block formal adoption until an explicit current-code resolution. Unreviewed first artifacts save as drafts with session-only trial data; explicit first use requires no known data blocker. Draft executable code lives in `draftResult`, while the legacy `result` is an inert notice so old clients cannot execute a draft against formal data. Adoption never copies trial data. Saved v1 QA and v2 Reviewer histories retain their types. See ADR 0011 for the superseded delivery policy.

Tests:

- `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`.
- `METAGPT_PROJECT_ROOT=... <venv>/bin/python runtime/team/test_runner.py`: zero-network native routing, exhausted budget, deadline and cancellation.
- `tests/team/fixture_transport.py`: explicitly scripted provider, never a real model. A test-only launcher can invoke it with `runner.py`; use `DEEPSEEK_API_KEY=offline-test-placeholder` and `TEAM_FIXTURE=1` for `tests/browser/team.spec.ts`.
- Existing UI/storage regressions use `team-fixture.ts` with explicitly synthetic review and role records. They do not provide real model review evidence.

Actual provider runs, target deployments and all failed attempts are recorded separately in `docs/verification/issue-25.md`.

Stop closes the task connection and kills the supervised process; the page ends waiting immediately and rejects late results. Requirements may return collected clarification questions or an unsupported limitation with a feasible alternative; these end execution rather than wait server-side. A user supplement starts a new task and preserves earlier questions in the current page session. Explicit terminal outcomes are passed, issues, rejected, failed, stopped, limit, clarification and unsupported. Modifications include full baseHtml and successful requirement context, never business records; candidate adoption binds the latest artifact-producing task to the code hash.

Cross-application delivery acceptance is documented in `docs/verification/issue-28.md`. `node --import tsx tests/team/live-cross-app.ts` prints a zero-network synthetic-input manifest; `--execute` is only for an explicitly authorized target and an empty evidence directory. Independent browser checks and handwritten offline fixtures remain developer evidence, never Reviewer actions. The standalone QA observation command `wait-for` waits at most two seconds for an exact read-only DOM value and fails if unmet; task deadlines and expected values remain unchanged.

Account cloud writes use ordinary user JWTs plus server HMAC attestations, with a persistent one-time task claim before spawning. Task tickets now contain the verified generation binding; old clients supplying arbitrary baseHtml/context must refresh. Natural Auth expiry does not invalidate an already pinned socket, but cannot authorize a new task or save. Explicit logout closes the socket. See ADR 0016.
